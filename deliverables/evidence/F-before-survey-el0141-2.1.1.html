Case for a failure

The element uses 'onmouseover' and 'onmouseout' exclusively for visual state changes, with no keyboard equivalents. More critically, the link inside uses 'onfocus="blur();"' which actively removes focus the moment a keyboard user reaches it, making the navigation link completely inoperable via keyboard. This is a direct failure of 2.1.1: keyboard users cannot activate this navigation item.
Quoted: "onfocus="blur();""; "onmouseover="switchImage('nav_news', './img/nav_news2.gif'); ChangeColor('news','#FFF')""; "onmouseout="switchImage('nav_news', './img/nav_news.gif'); ChangeColor('news','#EDEDED')""; "Ensure the functionality provided by mousing over this element is available through the keyboard"
Strength: 5/5

Case against a failure

The onmouseover and onmouseout handlers only change visual styling (image swap and background color). These are purely decorative hover effects. The actual navigation functionality is delivered by the anchor element with href='javascript:location.href=\'news.html\';', which is keyboard-reachable. However, the anchor uses onfocus='blur()' which immediately removes focus, making the link itself inoperable by keyboard. No honest pass case exists.
Quoted: "onfocus="blur();""; "javascript:location.href='news.html';"
Strength: 1/5

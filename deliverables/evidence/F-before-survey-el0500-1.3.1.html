Case for a failure

This table uses visual positioning to associate form labels with inputs. The text 'eMail Address' appears in a second row beneath the input field `id="em"`, and 'Retype eMail' beneath `id="ev"`, creating a visual label relationship. No programmatic association exists: no `<label>` elements, no `for` attributes, no `aria-label`, and no `<th>` elements. The structure and relationships conveyed through presentation cannot be programmatically determined.

Case against a failure

The scanner identifies this as a layout table, not a data table. The table uses 'border="0"' and contains form fields arranged visually, confirming it serves a layout purpose. WCAG 1.3.1 does not require layout tables to have header cells. The criterion applies to data tables needing structural markup; a layout table used purely for visual positioning of form elements does not convey data relationships that require programmatic structure.
Quoted: "This table appears to be a layout table"; "border="0""
Strength: 2/5
